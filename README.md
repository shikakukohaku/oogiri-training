# 大喜利発想トレーニング

大喜利の回答を「センス」に頼らず、**発想のプロセス**として訓練するためのWebアプリ（MVP）。

お題 → 連想を広げる → 深掘る → 離れた枝を繋ぐ → ずらす → 一文に圧縮する、
という思考の流れをマインドマップ上で可視化する。

AIは使わない。回答を作るのはユーザー自身で、アプリはその発想を誘発することに徹する。

このMVPで検証したい仮説：

> マインドマップ形式で考えると、普通に考えるより面白い回答が出しやすくなるか。

## 起動

```bash
npm install
npm run dev
```

`http://localhost:5173/` が開く。

```bash
npm run build    # 型チェック + 本番ビルド
npm run preview  # ビルド結果の確認
npm run lint     # oxlint
```

Node.js 20 以上を想定。バックエンドは無く、データはブラウザの LocalStorage に保存される。

見出しと本文には Google Fonts の Zen Maru Gothic / Rampart One を使う。
読み込めない環境ではヒラギノ丸ゴ → 游ゴシックの順にフォールバックするだけで、機能には影響しない。

## 使い方

画面は1枚。上にお題、中央にマインドマップ、右に発想支援、下に回答候補。

### ノードを増やす（テンポ重視）

1. マップ上のノードをクリックして選ぶ
2. `Enter`（マップにフォーカスがある状態）で下の入力欄へ
3. 言葉を打って `Enter` → 選んだノードの子として生える

- `Enter` … 追加。追加先は変わらないので、同じ親に続けて言葉を並べられる
- `Shift+Enter` … 追加して、そのまま新しいノードを追加先にする（深掘りモード）
- `Esc` … 追加先の固定を解除
- ノード右下の `+` … そのノードを追加先にする
- ダブルクリック … ノードの書き換え
- `Delete` / `Backspace` … 選択ノードを削除（子孫ごと）
- `Ctrl/Cmd+Z` / `Ctrl/Cmd+Shift+Z` … Undo / Redo
- `R` … ランダム飛び地

カテゴリ（モノ / 行動 / 特徴 / 感情 / 常識 / 状況 / 言葉）は任意。未分類のままでも困らない。

### iPad・タッチ端末

hover が無い端末では、接続点とノードの `+` ボタンを最初から表示する。
`Shift+クリック` の代わりに「線でつなぐ」→ 2つタップで枝を繋げる。
入力欄は 16px 以上にしてあるので、iOS Safari で勝手に拡大されない。
縦積みのレイアウトでは「線でつなぐ」「煮詰まった」を入力欄のすぐ下に置いている。

### あるある（ずらす対象）

**笑いは共有された前提を裏切って起きる**ので、裏切る対象は「みんなが知っていること」
でなければならない。誰も知らない事実は、崩れる期待が無いので裏切れない。

そして**あるあるは単語ではなく文**である。

- 「スヌーズ」— 単語。裏切れない
- 「スヌーズは1回では絶対に起きない」— 命題。裏切れる

そのためノードには2種類ある。

| | 見た目 | 役割 |
| --- | --- | --- |
| 単語 | 付箋 | 連想を広げる |
| あるある | 紫の帯が付いた横長のカード | 共有された前提。**ずらしの対象はこちら** |

入力欄の左で切り替える。単語ノードを選んで「あるある」にすると、その言葉について
一文を書ける。ずらし演算子は単語にも使えるが、単語を選んでいるときは
「先にあるあるを出そう」と促す。

思考の順番はこうなる。

```
お題 → 単語を広げる → あるあるに落とす → ずらす → 一文にする
```

### お手本（AIの代役）

あるあるを出すのが苦手な人向けに、「お手本を見る」で例を5件出せる。
本来は AI に出させたい部分だが、いまはプリセット（`src/data/aruaru.ts`、42語 × 5件）で
代用している。用意の無い言葉ではその旨を表示し、**どの言葉で外したかをログに残す**
（本物のAIにする価値があるかを判断する材料になる）。

**その言葉について自分で1つ書くまで押せない。**コストの都合ではなく、
先に自分で答えを出してから見本を見る方が身につくため。苦手な人ほど、
見本を先に見ると自分で考える回路を通らずに終わる。

お手本から取り込んだノードは点線で表示し、`source: 'hint'` として記録する。
リザルトでも「自力 n ／ お手本から n」と分けて出す。AIありの回となしの回で
最終回答がどう変わるかを、後から比べられるようにするため。

### 離れた枝を繋ぐ（このアプリの核）

親子関係だけでなく、**関係のない枝どうしを線で繋げる**。

- ノードの縁に出る点をドラッグして、別のノードにドロップする
- または2つのノードを選んで（`Shift+クリック`）「2つを線で繋ぐ」
- 指で操作しているときは「線でつなぐ」を押してから、繋ぎたい2つを順にタップする

繋いだ瞬間に右上のカードに `A × B` が出る。ここがボケの種になる。

### ずらし

ノードを選んで演算子を押すと、カードが出るだけ。回答は生成されない。

逆転 / 過剰化 / 矮小化 / 擬人化 / 視点変更 / 異業種化 / 文字通り化 / 組み合わせ（2ノード）

### ランダム飛び地

「🎲 煮詰まった」で無関係な単語が1つ出る（約180語）。
選択中のノードと無理やり繋ぐことで、自分の連想の外側に出る。

### お題を自分で作る

上部の「＋お題」から自分のお題を追加できる。

- 「お題」に一文を入れると、マップ中央に置く言葉が自動で埋まる。気に入らなければ直す
- 「追加して始める」でそのお題のマップが立ち上がる
- 作ったお題はブラウザに保存され、上部のプルダウンに「作ったお題」として並ぶ。
  「次のお題」でもプリセットと一緒に回ってくる
- 同じパネルの一覧から削除できる。ただし今まさに挑戦中のお題は消せない
  （マップが宙に浮くため）

### ステータスとミッション

- 発想量（総ノード数） / あるある（あるあるノード数） / 広さ（お題の直下） / 深さ（最大Depth） / 横断（異なる枝を繋いだEdge数） / ずらし（使った演算子の種類数）
- ミッションは「言葉を5個 → あるあるを3つ → あるあるをずらす → 枝を繋ぐ → 回答を3つ」の順に出る

### 回答

下部に回答候補を最大5つ。「これで回答」でリザルト画面になる。
リザルトから「もう一度」「次のお題」「マップに戻る」。

## データとログ

LocalStorage のキー：

| キー | 中身 |
| --- | --- |
| `oogiri-training/session/v1` | 進行中のセッション（お題 / ノード / エッジ / ずらし履歴 / 回答 / ミッション達成） |
| `oogiri-training/topics/v1` | 自分で作ったお題 |
| `oogiri-training/logs/v1` | 完了したセッションのログ（最新200件） |

ログに残す項目：セッション開始・終了時刻、所要時間、作ったノード数、消したノード数、最大Depth、Cross Edge数、使用したOperator、飛び地の回数、回答数、最終回答、あるある数（自力／お手本から）、お手本を開いた回数、お手本が無かった言葉。

上部の `JSON` / `CSV` ボタン、またはリザルト画面から書き出せる（現在進行中のセッションも含む）。
「リセット」で今のお題をやり直せる。

## GitHub Pages で公開する

1. リポジトリの **Settings → Pages → Build and deployment → Source** を `GitHub Actions` にする
   （これを先にやらないとジョブが落ちる。ワークフロー側からの有効化は `GITHUB_TOKEN` の
   権限では通らないので、この一手だけは手で行う。public リポジトリなら無料プランでよい）
2. あとは push するたびに `.github/workflows/deploy.yml` がビルドして公開する
3. 公開先は `https://shikakukohaku.github.io/oogiri-training/`

ワークフローは `main` への push で動く。`github-pages` 環境の保護ルールにより、
デフォルトブランチ以外からはデプロイできない（作業ブランチから公開したい場合は
Settings → Environments → github-pages にそのブランチを追加する）。

リポジトリ名のサブパスで配信されるため、ビルド時の `base` は `/oogiri-training/` にしてある
（`vite.config.ts`）。`npm run dev` は今までどおり `/` で動く。
ルート直下や別のホストに置くときは `BASE_PATH=/ npm run build` のように上書きする。

## 見た目について

リソグラフの刷り物をイメージしている。生成りの紙、太い黒の輪郭、版ズレのようなオフセットの影、
網点、ハイライターの線。ノードは付箋のように少しずつ傾いていて、枝ごとに色が割り当てられる
（この色分けのおかげで「離れた枝を繋いだ」ことが一目で分かる）。
枝線は定規で引かない：id から決まるゆらぎを持たせた手描き風の曲線を2本重ねて描いている。

## 技術構成

- React 19 + TypeScript + Vite
- [React Flow (@xyflow/react)](https://reactflow.dev/) … グラフ表示・接続
- Zustand（`persist` で LocalStorage 保存）

```
src/
  components/   画面パーツ（MindMap / IdeaNode / QuickAdd / 各パネル / リザルト）
  data/         お題・カテゴリ・ずらし演算子・ランダム単語・あるあるのお手本
  lib/          木構造とスコア計算 / レイアウト / ミッション判定 / ログ
  store/        セッションの状態（Undo/Redo 込み）
  styles.css
```

## MVPでやっていないこと

ログイン、DB、AI API、AIによる回答生成・採点、課金、ランキング、オンライン対戦、SNS連携。
